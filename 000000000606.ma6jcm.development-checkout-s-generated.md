## Goal
A development checkout's generated addresses follow its slot, so a stale value can't send the dev server to another slot, and two slots on one host keep separate sign-ins.

## Purpose
The test checkout still held SERVER_REST_URL=http://proxy:80 and STATBUS_URL=http://localhost:3013 from an earlier setup: the host dev server's auth check failed with ENOTFOUND proxy on every request, and the page reloaded to /login in a loop (owner 2026-11-16 13:06). BROWSER_REST_URL pointed at another slot's REST (localhost:3013). Each new checkout or reboot repeats the diagnosis.

## Principle
In development the addresses are derived from SITE_DOMAIN and the slot, not remembered; a value that differs is an explicit operator override, never a leftover.

## Relevant details
In development, sb config generate derives STATBUS_URL, BROWSER_REST_URL and SERVER_REST_URL from SITE_DOMAIN and the slot's ports, but writes them to .env.config once and then keeps whatever is there (gen() fills only missing keys).

Design to decide: in development mode, sb config generate either derives these three from SITE_DOMAIN and the slot (unless the operator declares an override explicitly), or refuses with the expected value when a declared value names another slot's port or a docker-only host; pnpm run dev runs the same check before starting.

## Acceptance
- [ ] In development, after sb config generate, SERVER_REST_URL, STATBUS_URL and BROWSER_REST_URL in .env name this checkout's SITE_DOMAIN and slot ports (Go test with a .env.config holding http://proxy:80 and another slot's port)
- [ ] pnpm run dev refuses to start, naming the key and the expected value, when .env still holds an address the dev server can't reach
- [ ] In the test checkout, a fresh pnpm run dev after ./dev.sh https on signs in at https://local.statbus.org:3031 without hand edits
- [ ] Two slots on the same host (local.statbus.org:3011 and :3031) stay signed in side by side: signing in on one leaves the other signed in (observed in Firefox)
