## Goal
Opening an edit on the Live frame and switching to the Timeline shows exactly what the edit changes: only Live's part of a value that spans several frames is ticked, and an edit that does reach a past frame asks before saving.

## Purpose
Owner review 2026-11-17 13:22 on LU 29 Name and Sector: the edit was on Live (2026-01-01 – Present, as 'Changes' said), but the Timeline showed one ticked card 2024-01-01 – Present with its old value struck out, as if 2024 and 2025 changed too, and no past-frame question appeared. Remove already splits a value into one piece per frame; Change lost that in the 2026-11-16 refactor.

## Principle
The Timeline shows what Save does. A tick means that period changes, so a value spanning frames is cut at frame edges, as Remove does, and the past-frame question follows the ticked pieces.

## Relevant details
Ticks are read back from the edit's dates with periodsInRange (overlap), so a period that only overlaps the edit is ticked whole. Remove uses frameSegments pieces (remove-record-button.tsx useRemovalPieces). Owner screenshots: Name 'EDIT PAGES ASA -> EDIT PAGES AS 2024-01-01 – Present', Sector '4500 -> 1110 2024-01-01 – Present', both 'Changes 2026-01-01 – Present'.
