## Goal
Uganda's 1.9 MB region file stores via Upload Regions, and a failed upload says what went wrong and what to do.

## Purpose
statbus.ubos.org 2026-11-27 10:43-13:48 UTC, v2026.11.6: 14 attempts at /getting-started/upload-regions each answered 500 with app log 'Body exceeded 1 MB limit' (Next server-action default bodySizeLimit). The file never reached PostgREST, so the team was stuck on a generic error. Small files (892 B, 19 KB) stored fine.

## Principle
Send the upload straight from the browser to /rest (AGENTS.md: prefer browser-to-/rest), so no server-action body limit applies; keep the plain-language explanations of PostgREST rejections.

## Details

The owner believes it was an Excel file (screenshots due Monday); the browser converts Excel to CSV before the server action, so the limit applies either way. Path: upload-csv-form.tsx -> server action uploadFile (getting-started-server-actions.ts) -> fetch POST /rest/region_upload. Also check the per-row INSTEAD OF trigger admin.region_upload_upsert finishes a large file within authenticated statement_timeout 120s. Log copy: tmp/uganda-2026-11-27.log.

Plan-cache fix chosen by rabbit, not an owner decision: ALTER FUNCTION admin.region_upload_upsert SET plan_cache_mode = force_custom_plan keeps the trigger's tested semantics (test 414) and measured 58k rows in 29.9 s; a set-based rewrite would change its per-row error reporting and is not needed to meet 120 s.
Root cause of the slow store (corrects the 22:48 note): on Uganda region has reltuples 0, relpages 1 (read-only check 23:14; autovacuum 11:24, autoanalyze 11:29 while empty).
