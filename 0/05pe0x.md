## Goal
Every data-quality check is one catalogue row with a plain name, an ⓘ explanation and a switch, its failing units in one findings table.

## Purpose
Installations have several summed statistical variables and want to choose which checks they see; today's checks are vaguely named, the triangle on a card explains nothing, every check is its own table and card, and six Data quality cards cost six slow statistical_unit counts per dashboard load (fc9xbd).

## Principle
The database ensures consistency: the rules are an enum, a per-variable rule always names its variable and no other rule does (CHECK), switches and findings go when their variable is deleted (ON DELETE CASCADE), and the list of checks is a view over the enum and the enabled summed variables, so it follows the variables by itself. Only switched-off checks are stored: every check starts on, a new variable's checks too. Switched off means hidden from the dashboard and the Quality filter. Failing units are computed in the derive pipeline (worker.derive_quality), never by row triggers. Wording lives in TypeScript keyed by the generated enum, so tsc fails if a rule has no name or explanation. Report cards join the same design later (owner's coming standard-reports ticket), not here.

## Details
Approved by the owner 2026-11-24 20:31 (design in chat; prototype tmp/ca6dk5/catalogue/prototype-finding.sql/.log). SCHEMA. CREATE TYPE public.quality_rule AS ENUM ('missing_region', 'missing_activity_category', 'missing_physical_location', 'establishment_activity_differs', 'establishments_above_legal_unit', 'legal_unit_above_establishments'); public.quality_rule_per_stat(rule) IMMUTABLE, true for the last two. View public.quality_check: each non-per-variable rule once, plus each per-variable rule x enabled stat_definition of type int or float, with on_dashboard = no row in quality_check_switched_off. Table public.quality_check_switched_off (rule, stat_definition_id REFERENCES stat_definition ON DELETE CASCADE, UNIQUE NULLS NOT DISTINCT (rule, stat_definition_id), CHECK quality_rule_per_stat(rule) = (stat_definition_id IS NOT NULL)); admin_user writes, authenticated reads; reset scope customisation empties it. Table public.quality_finding (rule, stat_definition_id ON DELETE CASCADE, unit_type, unit_id, valid_from, valid_until, valid_range generated, existence_from and existence_until copied from statistical_unit, detail jsonb with the compared numbers; UNIQUE NULLS NOT DISTINCT (rule, stat_definition_id, unit_type, unit_id, valid_range); the same CHECK; NOT ENFORCED period FK to statistical_unit; index (rule, stat_definition_id, existence_from, existence_until)). It always holds every check, so switching one on shows its number at once. MIGRATION. A forward migration replaces quality_establishment_activity_differs (released in v2026.11.6, migration 20261118134950) and quality_establishments_above_legal_unit / quality_legal_unit_above_establishments (migration 20261124115435, on master, not in a release, left unedited) with quality_finding; rows are recomputed by derive_quality, which the migration enqueues. reset's TRUNCATE lists name quality_finding. Hibiscus's planned quality_domestic_without_region (feat/units-on-map, migration 20261124150723, z2qt08) becomes the missing_region rule here: domestic AND physical_region_path IS NULL AND physical_country_id IS NOT NULL, legal units and establishments (pkne34); coordinate the branch. Missing activity category = primary_activity_category_path IS NULL; missing physical location = physical_country_id IS NULL; both for legal units and establishments (QUALITY_CARD_UNIT_TYPES). CONSUMERS. Search: ?quality=<rule> or ?quality=<rule>:<stat code> becomes select=*,quality_finding!inner()&quality_finding.rule=eq.<rule>[&quality_finding.stat_definition_id=eq.<id>]. Dashboard: one request quality_finding?select=rule,stat_definition_id,count()&existence_from=lte.D&existence_until=gt.D gives every card's number (Norway prototype 45 ms; 2,307,685 rows, 202 MB, filled in 16 s). Admin: page 'Data quality checks' with one switch per quality_check row; dashboard says 'N switched off · Edit' (Edit for admins). Names: per-variable rules read '<stat_definition.name>: establishments add up to more than the legal unit' and '<name>: legal unit has more than its establishments, all of which have numbers'. Related: ca6dk5, 217dx5, fc9xbd, pkne34, z2qt08.
