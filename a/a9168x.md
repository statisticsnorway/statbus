## Goal
The installation fetches the map tiles its users view from OpenFreeMap once and serves them from its own cache after.

## Purpose
Owner 2026-11-27 22:33: installations have outbound internet but are not reachable from it; on slow lines the remote tiles are the bulk of a map's wait. A whole country file was held back for its size; a cache stores only what is viewed and makes repeat views fast and local.

## Principle
Fetch a tile from OpenFreeMap only the first time it is asked for, keep it for a long time (base tiles change rarely), and bound the cache's disk use so it cannot fill the server. The browser asks the installation, never OpenFreeMap directly. Switching the source is configuration, not code: the map component names its style in one place.

## Details
Today components/map/basemap.ts points the browser at tiles.openfreemap.org (style, fonts, sprites, vector tiles). The cache sits in front of it on the installation (Caddy, which already fronts the app, or a small cache service), with long lifetimes for tiles, fonts and sprites and a size bound that evicts the least used. The style JSON's tile URLs are rewritten to the installation's own path. A full country PMTiles file (Protomaps extract) stays possible later for an installation without internet; not needed now.

## Notes

2026-11-27 22:31 owner (testing on throttled 3G): for the maps, loading the base tiles from the remote network will be a bigger problem than waiting for our own results; the map's own data reads are small (about 2 KB per level on the Reports Map). Self-hosted tiles from the installation shorten that path; linked from ez5thj (every page loads fast on a slow network).

2026-11-27 22:32 owner idea, an alternative to a whole country file (he held back because the file takes too much space): the installation's server caches the tiles it is asked for. Caddy proxies tile requests to OpenFreeMap and keeps each tile fetched, so only the areas and zooms people actually view are stored, and later viewers get them from the installation for a long time (base tiles change rarely). Gains: small storage that grows with use, fast repeat loads, less dependence on the third party at run time. Limits: the first viewer of an area still waits on OpenFreeMap, and a network without internet still needs the file. To decide with the owner after the release: file, cache, or both (the cache as default, the file for closed networks).

2026-11-27 22:33 owner decided the direction: every installation in use has outbound internet (its users reach the internet) but is not reachable from it. So the server fetches tiles on behalf of its users (little overhead) and keeps them a long time: once an area has been loaded, every later view of it is fast and local, without burning out the server. The cache is the plan; a whole country file is no longer needed.
