# STATBUS-219: paths whose changes CANNOT affect any test outcome, build
# artifact, or runtime behaviour. When a prerelease VERDICT gate (pg_regress,
# go-test, app-build-lint, fast-tests) is not green at the tip, the preflight
# (cli/cmd/release.go) may accept a green run at the nearest first-parent
# ancestor whose DIRECT diff to the tip changes only paths listed here — the
# ride is printed loudly, naming the ride target and the run it verified,
# with a count of how many files changed since (all exempt per this file).
# STATBUS-275 (King's ruling): the per-file enumeration was softened to a
# count — the ride is still loud and still auditable, an operator who wants
# the file list runs the same diff this check ran.
#
# MATCHING IS AN ANCHORED PATH PREFIX. The sensitivity policy next door now
# also uses explicit repository-root exact/directory/prefix matchers, but it
# answers a different question and has its own typed reasoned parser. Here the
# failure direction is strict: over-inclusive matching would treat MORE commits as
# needing no tests, i.e. wave untested code into a release. So an entry
# matches a changed file only when the file's repo-root-relative path (as
# `git diff --name-only` prints it) BEGINS with that entry: `.backlog/`
# matches `.backlog/tasks/x.md` and never `app/src/.backlog-widget.ts`.
# One entry per line; blank lines and lines starting with # are ignored.
#
# THE IMAGES GATE NEVER RIDES, whatever this file says — that stays true.
# The other four gates ask "did this content pass?", and content identical
# to a tested ancestor has demonstrably passed. images asks "do the Docker
# artifacts EXIST at this SHA?" — no argument about markdown makes an image
# materialise at a SHA nothing published to. The Go-side ride exclusion is
# enforced in code, not by this list.
#
# STATBUS-219 STAGE 2: images.yaml ALSO reads this file now, for a DIFFERENT
# question than "ride" — not "can I skip proving this content", but "is a
# byte-for-byte copy of the parent's already-published images enough,
# instead of rebuilding from source". The artifact still gets published at
# every commit unconditionally, so this is not the images gate riding; it is
# the images WORKFLOW choosing how cheaply to satisfy the same unconditional
# publish invariant. images.yaml's own `decide-exempt-only` job carries a
# bash reimplementation of the exact matching rule below (fileIsCIExempt in
# cli/cmd/release.go), since GitHub evaluates a workflow's own trigger-time
# logic before any Go binary is built — kept in sync BY HAND with the Go
# original; flag any drift you spot.
#
# ALSO A THIRD, STATIC COPY: go-test.yaml and app_build_and_lint-workflow.yaml
# each carry a `push.paths-ignore` list (GitHub's own server-side trigger
# filter — it cannot read this file at trigger-evaluation time either) that
# must list the SAME exempt paths as this file, or a board-only push either
# needlessly runs those two workflows or — worse — silently stops running
# them for a path that was never actually exempted here. Adding an entry
# below means updating THREE places, not one.
#
# `migrations/` AND `test/` MUST NEVER BE ADDED. Beyond the obvious (they are
# test inputs), the ride's pg_regress arm depends on it: on a ride the preflight
# feeds the stamp checks the RIDE TARGET's SHA and lets them diff
# stampSHA..HEAD for migration and test/expected drift. That diff is empty BY
# CONSTRUCTION only because those paths are not exempt. Exempt either one and
# the drift checks would silently stop being able to see the very drift they
# exist to catch.
#
# ADDING AN ENTRY IS A GATED ACT. Changing what counts as test-irrelevant can
# never itself ride a prior green: this file is deliberately NOT exempt (it is
# under ops/, which is absent here on purpose), and a test asserts that it
# matches no entry in its own list. Each new entry ships as its own argued,
# ratified addition — `doc/` is the obvious next candidate and is deliberately
# NOT included here.
