## Goal
A workflow sets each unit's size (tiny, small, medium, large) from rules on statistical variables such as employees and turnover, producing an import job with the changes.

## Purpose
Unit size is today set by hand or by import. Countries define size by thresholds on several variables, and the size should follow the data, reviewably (owner notes 2026-11-18).

## Principle
One workflow on the Workflows page (xhxnsy), not an automatic trigger: it proposes, an import job applies. Rules are data in a table, not code. All rules for a size are combined with AND; a variable a unit has no value for is ignored.

## Relevant details
Owner's example, 2026-11-18. Limits: tiny employees <10, turnover <3m; small <50, <10m; medium <200, <75m; large >=200, >=75m. Proposed table unit_size_rule (stat_var_code, unit_size_code, greater_or_equal): employees tiny NULL, small 10, medium 50, large 200; turnover tiny NULL, small 3000000, medium 10000000, large 75000000. Combine all rules with AND. If missing then ignore. Existing: public.unit_size (code, name, enabled, custom).

## Acceptance
- [ ] [Owner] Confirms the rule semantics: how a unit that meets one variable's 'large' and another's 'small' is sized under AND, and which frame's values are used; the answer is recorded in the notes
- [ ] A unit_size_rule table holds the rules with a foreign key to unit_size and stat definitions, and a SQL test asserts the size computed for units at and around each limit, including a unit missing one variable
- [ ] Running the workflow on a frame produces an import job that changes exactly the units whose computed size differs from their current size
