## Goal
A person who spots a unit's data problem flags it with a reason, finds all flagged units later, and clears the flag once fixed.

## Purpose
Data problems are noticed in passing, e.g. Vinmonopolet's three establishments 'at their address' have placeholder coordinates (9,58; 9.5,59.5; 9,59), 'Administrasjon Bergen' plotted near Kongsberg. Nobody fixes it on the spot, and today there is no way to record it and come back: quality checks only cover what a rule can detect, and unit notes are free text one per unit that nothing lists (owner 2026-11-24).

## Principle
A flag is a person's judgement, kept apart from the rule-based quality checks; it is found the way quality problems are found (a search filter with a visible chip, a dashboard card whose count equals its list). It does not change the unit's data and is cleared, not deleted, so the record of who flagged and resolved it remains.

## Details
Flagging happens wherever a unit is seen: a map's unit list, a report, a unit page. Options to decide with the owner: (a) build on unit_notes (one note per unit, already on every unit page) with a 'needs review' state; (b) a separate unit_review_flag table, several per unit, each with reason, flagged_by, flagged_at, resolved_by, resolved_at; (c) show flags as a quality check 'Flagged for review' in search's Quality filter. Found while reviewing the units map (z2qt08). Placeholder coordinates could also get a rule-based check (coordinates far from the unit's region), a separate task if wanted.
