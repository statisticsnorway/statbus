## Goal

The legal unit, establishment and enterprise history pages load every version of the unit from statistical_unit in one request, ordered oldest first, and draw them all (getStatisticalUnitHistory in app/src/components/statistical-unit-details/requests.ts). Locally the largest unit has 25 rows (average legal unit 3), but each change to the unit or its locations, activities or statistical variables adds a row: a unit changed by a monthly import gains about 12 a year, hundreds over a decade. Design (owner 2026-11-16): newest first, 50 at a time; a 'Show 50 older' button fetches the next page from the database (range request), so the page never reads the whole history; the heading states the count ('Showing 50 of 312'). The dimming of repeated cells (93accb154) keeps working across page boundaries. The chart is summarised per year and stays as it is.

## Purpose
A unit changed by a monthly import gains about 12 versions a year; reading and drawing all of them makes the history page slow and long, and the newest changes are what a user looks for first.

## Principle
The page reads from the database only what it shows, newest first; the count tells how much more there is.

## Acceptance
- [x] #1 The history table lists a unit's newest 50 versions first, and reads no more than that from the database (request uses range/limit)
- [x] #2 'Show 50 older' appends the next 50 older versions, and is absent when none are left
- [x] #3 The heading states how many versions are shown and how many the unit has
- [x] #4 A cell that repeats the version below it in time is dimmed, also for the last row of a page (compared with the next older version)
