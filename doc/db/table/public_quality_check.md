**Comment:** Every data-quality check of this installation with its integer id (h9mhxe): each rule that is not per variable once, with a fixed id (1 missing_region, 2 missing_activity_category, 3 missing_physical_location, 4 establishment_activity_differs, 7 secondary_activity_equals_primary), and each per-variable rule once per summed variable (stat_definition of type int or float), with an id from 101 up given when the variable is created and kept by the stat_definition lifecycle callback (public.quality_check_catalogue_generate / _cleanup). The id is what findings store: a row check in statistical_unit.quality_check_ids, a relation check as check_id in its table (public.quality_establishment_activity_differs, public.quality_legal_unit_establishment_stat). It is never reused, so a stored id always names the same check. Readers show the checks public.in_use says apply. Admins switch checks on Admin > Data quality checks (switched_on).
