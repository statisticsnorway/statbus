*Canonical source of truth for the upgrade/recovery **decision logic**. Lifted into `doc/` from the backlog (2026-06-29) so it sits with its siblings — `doc/upgrade-timeline.md` (when things happen), `doc/upgrade-vocabulary.md` (the names), and `doc/diagrams/` (the pictures). The glossary names these concepts, the diagrams draw them, the code implements them; this is where they reconcile.*

Status: **shipped model** (ratified as target 2026-06-27; run-proven through the install-recovery arc campaign, culminating in the health-park arc's full green, wave 10, run 29171998401). Enabled by the read-only window (read-only-upgrade-window design · STATBUS-110) + error classification (STATBUS-109). **The window formally supersedes STATBUS-039's "never restore on a guess" (STATBUS-110 AC#3, 2026-07-12)** — see the supersession statement in `doc/read-only-upgrade-window.md` §"Effect on recovery".

## Principle
*You cannot go wrong without intent; with intent you're allowed. Don't act on what you can't name.* Recovery is **autonomous in every case except two** principled human stops.

## The model, end to end

### 1. Read the recorded state (the `upgrade-in-progress` marker)
- **no marker** → nothing to recover; normal startup. [auto]
- **corrupt / unreadable marker** → discard-and-log only after acquiring its canonical flock; a live holder keeps the marker and recovery fails closed. [auto]
- **install-holder marker** (a crashed install, not an upgrade) → clear it; no DB work. [auto]

Every mutation of a held recovery marker is a durable atomic replacement: write
and fsync a temporary file in `tmp/`, acquire the flock on that replacement
inode, rename it over the canonical marker, fsync the directory, then release the
superseded inode. A crash before rename leaves the old complete JSON; after
rename the new complete JSON is already locked. No truncate-in-place window may
erase recovery-critical fields such as the recorded source image identities.
Fresh marker creation uses the same writer but installs the already-locked temp
inode with a no-overwrite hard link, so a racing intent can never be replaced.
Abandoned sibling `.upgrade-in-progress.json.tmp-*` files are scavenged only
while the canonical marker flock is held and its descriptor/path identity has
been revalidated. Every in-tree replacement writer holds that same canonical
flock before creating its temp; fresh creation is the only exception and occurs
before any canonical path exists, then scavenges after its already-locked inode
becomes canonical. A live locked temp is left alone. This ownership protocol
serializes validate/unlink against every in-tree writer; a same-user local
process deliberately replacing marker temp paths outside the protocol is out of
scope. Every path-based flock acquisition closes the complementary open-before-rename
race: after taking the lock it compares the held descriptor with the canonical
path using `fstat` + `stat` + `SameFile`. An orphaned pre-rename inode is closed
and retried a bounded number of times; unresolved identity fails closed rather
than creating two apparent mutex owners.
- **unrecognized phase value** → STOP for a human (we can't read our own recorded state). [HUMAN — "unknown"]
- **recognized phase** (pre-swap / post-swap) → continue.

### 2. Decide direction (the read-only window makes any rollback data-safe)
- **pre-swap** — never booted the new sb → roll back trivially (restart old; nothing changed). [auto]
- **post-swap, at-target** — new binary + migrations in place → continue forward (finish remaining steps). [auto]
- **post-swap, behind** — migrations didn't run / binary not at target (deterministic) → roll back. [auto]
- **post-swap, can't read position** — DB unreachable / target commit not in clone → an *intermittent* error → §3.

### 3. When a step fails — classify the error, then act (the no-spin rule)
- **Intermittent** (recognized transient) → **`backoff-retry`**, in-process + heartbeating; resolves → continue, exhausts → no longer transient → **roll back**. One strategy, two cases, parameters + failure-detection tuned per probe:
  - `db-unreachable` — probe = connect + trivial query; one try fails on a wall-clock **5s** (a quick check, never a transfer); gap 1s→2s→4s→8s→16s→30s cap; **~5 min** budget.
  - `commit-not-fetched` — probe = one `git fetch`; one try fails on a **stall** (no progress ~60s, git low-speed) — **never a deadline**, so a healthy slow transfer is never cancelled; gap 10s→30s→60s; **~15 min** overall budget.
  - Health checks (DB-health / REST-ready / health-RPC) already self-wait → rollback on exhaustion; **not** on this path. *(Values build/test-reconcilable; the shape is fixed.)*
- **Persistent** (recognized deterministic: "relation already exists", a constraint violation) → zero retries (retry can't change a deterministic outcome), then **branch on observed position** (STATBUS-046, shipped): positively **behind** the target → **roll back** (data-safe by the window); **at-or-past target, or unverifiable** → **PARK** (`recovery_parked_at` set, row stays `in_progress`, siren once, unit alive-idle — rolling back an at-target box could strand post-maintenance-off integrator writes, and retrying a deterministic failure cannot help). A parked box waits for the fix: deliberate un-park (`./sb install` / re-schedule), or **displacement-at-claim** (STATBUS-159 — a newly scheduled release's claim atomically moves the parked row to `superseded`, park reason preserved, and proceeds).
- **Unknown** (unrecognized error) → **STOP for a human.** Don't retry (might spin); don't roll back (might be wrong for an error we don't understand). Mechanically: stays in_progress + loud; the existing systemd-StartLimit exit-restart backstop surfaces it. [HUMAN — "unknown"]

**Composition with the existing backstop:** the in-process `backoff-retry` sits *in front of* the systemd-StartLimit exit-restart (today these transients exit→systemd immediately; the new in-process retry is genuinely new). A known transient that **exhausts → rolls back** here (the case-9 "stuck" spin stays dissolved); the systemd backstop remains *only* for the **unknown** stop. An exhausted *known* transient must never fall through to the old restart-until-stuck loop.

### 4. Terminals
- **completed** — forward succeeded, **serve-proven** (STATBUS-160/192): `completed` means *this version verifiably serves*, at **every** writer. Before the completed write lands, the writer has brought the app set up, passed the app health gate, turned maintenance off, and lifts the read-only window immediately after — the normal pipeline, the flagless heal (`completeInProgressUpgrade`, STATBUS-192), and the containers-at-target self-heal (`resumeNewSb`, STATBUS-071) all carry the same tail. A health failure past warm-up at target routes to **park**, never to a completed lie: a box that cannot serve is never certified. [auto]
- **rolled_back** — a rollback succeeded; source git and source-generated config are authoritative for the serving tier. Before any target pull, the upgrade marker records the running source app/worker/rest/proxy containers' immutable Docker image IDs. Recovery derives an explicit `ServingEra` by matching actual container image IDs against those recorded source identities, never by trusting mutable image names or tag suffixes. Every non-empty Compose `ImageID` is cross-checked against `docker inspect` for that exact container; disagreement names both identities and fails closed, while an omitted Compose field leaves the daemon identity authoritative. Digest references and the explicit `local` development sentinel are accepted only with resolvable immutable IDs; same-short rebuilds, moving tags, missing IDs, mixed identities, and ambiguous identities refuse by name. `Source` containers may start in place; a coherent `Target` is recreated as app/worker/rest/proxy only, with `--no-build --no-deps`, from the proven source model. Recovery then re-inspects and must freshly derive `Source` before the functional app/REST health gate. If recreation partly starts and errors, or reinspection is not `Source`, recovery actively stops app/worker/rest and positively verifies containment before returning the failure. Recovery failure terminals likewise never claim clients are stopped from control flow alone: they run the stopped-client verifier, narrowly contain app/worker/rest on a violation, positively re-verify, and persist whether containment was verified. Ordinary operator starts take the same canonical marker flock for their complete start operation: a live holder refuses with `./sb install` guidance, while absent and free parked/crashed markers remain startable. Held-closed recovery asserts that it retains the canonical flock continuously across precheck, DB/proxy start, and postcheck.

  **Compose-up authority threat model:** the gate proves the absence of accidental compose-up authority in recovery code. A well-intentioned change that reintroduces `docker compose up` on a failure branch fails CI. It does not defend against deliberate in-module subversion through `unsafe`, `go:linkname`, or reflection over process-local state; that is equivalent to editing the wrapper itself, and Go has no in-process capability security. Reviewers evaluate the gate against this contract. The design therefore has no bearer token: generic Compose construction parses global options, rejects `up` at the actual subcommand position, and fails closed on unknown global flags. `compose.Up` inserts the subcommand itself and its type-resolved function object may appear only as the callee of direct calls at the exact allowlisted sites. A whole-module `go/types` gate loads Linux and Darwin production variants, fails on package-load errors or uncovered production files, and resolves aliases and dot imports by object identity. Its process-launcher set is `os/exec.Command`, `os/exec.CommandContext`, `os.StartProcess`, `syscall.Exec`, `syscall.ForkExec`, `os/exec.Cmd` composite literals, and every generic `internal/upgrade` runner that reaches `commandContext`. Launcher function values are forbidden. Every constant production launch is pinned as the exact `(enclosing function, launcher kind, executable)` combination; unknown tools, new combinations, changed counts, and stale entries fail closed. `commandContext` has no runtime executable allowlist: its genuine runtime responsibilities are the invocation-scoped Git configuration and routing Docker through `compose.DockerCommandContext`. The few dynamic internal forwarding edges between generic runner layers are exact-count pinned, while every reviewed caller supplies a constant executable. Tools may receive dynamic path/SHA arguments. Raw launcher arguments may not carry `docker`, `docker-compose`, `podman`, or `compose` authority; calls through the typed upgrade runners with executable `docker` are permitted because `commandContext` sends them through the Compose parser. Mediators require compile-time-constant authority-free arguments except the exact-count-pinned pre-existing facilities whose contract is explicitly to execute an operator/user-configured command (seed-lock wrapper, dotenv generator, self-update verification, and callbacks); adding another call, even in the same function, fails the inventory. The three dynamic `syscall.Exec` process-replacement handoffs are exceptions pinned by both an adjacent `authority:pinned-reexec` marker and an expected count of one in their exact file/function; an added call in the same function, a missing marker, or a marker on a non-pinned call fails closed. The visible `up` inventory remains defense in depth. The rc.66→rc.67 prohibition is specifically against recreation from the wrong-era tree/config, not against source-authoritative recreation after source restoration. [auto] *Operator forecast (tailored to cause): a **hard / persistent-error** rollback → report it (log retained) + try a **later release** when available (the same version repeats the failure — don't re-schedule it); an **exhausted-transient** rollback → retry when the environment is healthy (same version is fine).*
- **failed** — a rollback was chosen but its *restore itself* broke (rsync/disk); box can't reach runnable. The out-of-volume recovery marker records the restore failure code and detail before any best-effort row mirror, and no serving container is resumed or recreated from that path. [HUMAN — "restore-broke"] *Shipped (STATBUS-111, closed 2026-07-12): the install ladder re-attempts the restore — a `failed` row with a retained `backup_path` is re-attemptable, **human-gated via `./sb install`** (never the auto systemd service — restore-broke stays a human stop, no auto-thrash); the operator sees a **legend** (`./sb install` headline + state-relevant commands) + a **forecast** (detected state + planned action). Two row classes: the pair-terminal re-attempt completes; an abort-row with corrupt git refuses actionably. Arc-proof obligation tracked on STATBUS-071's coverage map (restore-broke-reattempt row).* *One named exception (STATBUS-347): a healthy rollback records `ROLLBACK_FINISH_PENDING: <cause>` as a `failed` row BEFORE it lifts the read-only window or maintenance. That row means "the snapshot is already restored and the box is healthy on old; only marker cleanup and the final `rolled_back` transition remain". It is cleanup-only: the install ladder excludes it from restore re-attempt, `recoverFromFlag` intercepts its marker before any phase-based snapshot recovery, the daemon finishes it at startup and on each heartbeat (`finalizePendingRollbacks`, one row-locked transaction: remove the marker, then write `rolled_back`), and `claimScheduledUpgrade` refuses every new claim until it is finished. A second restore after writes were accepted would overwrite data, so nothing may restore again.*
- **parked** — not a row terminal but a held state (`in_progress` + `recovery_parked_at`, STATBUS-046/154): a deterministic at-target failure waiting for its fix. Alive-idle, sirened once, skipped by every automatic resume; leaves only by deliberate un-park or displacement-at-claim (STATBUS-159). Every state/park write is audited in `public.upgrade_state_log` (STATBUS-154). **The parked-skip invariant is enforced at every automatic path by name**: the flagless heal skips before its flag-cleanup defer even arms (`completeInProgressUpgrade`, STATBUS-135); the post-swap resume's budget section skips without consuming an attempt (STATBUS-046); and the containers-at-target self-heal — once the lone exception — carries a primary parked-read plus an atomic `recovery_parked_at IS NULL` guard on its completed write (STATBUS-193). No automatic path can complete a parked row, strip its flag, or consume one of its attempts. [auto-hold — operator acts at leisure, box never crash-loops]
- (a §1/§3 "unknown" stop → row stays in_progress + loud, waiting for the human.) [HUMAN — "unknown"]

## The shape
Autonomous everywhere **except two human stops**, both principled and rare:
1. **unknown** — we can't *read* the situation (an unrecognized phase **or** an unrecognized error). One rule: don't act on what we can't name.
2. **failed** — our recovery *action* (the restore) itself broke. Hands-on regardless.

## What enables it
- **Read-only window** (read-only-upgrade-window design · STATBUS-110): blocks *accidental* external writes during the danger phase (DB-back-up-for-migrations → resolve) → a rollback can never lose data → rollback is the universal safe fallback → "never restore on a guess" (STATBUS-039) retires; the can't-verify→hold→human spin dissolves; the at-target-spin (the 18-day rune hang — §"What actually went wrong on Rune") is gone. Accident-guard, not a lock (deliberate override allowed — the operator's escape hatch).
- **Error classification** (STATBUS-109): two curated lists — **known-intermittent** (→ backoff-retry) and **known-persistent** (→ roll back). Everything else is **unknown by default → stop.** Safe-by-default; no blind retry counts; no spin. Retries run in-process (not exit→systemd-restart), so they don't burn the restart budget.
- **Watchdog cover** (STATBUS-195): the systemd watchdog (`WatchdogSec=120s`, heartbeats every 30s) exists to kill a *hung* daemon — never a slow-but-live one. The rule: **every long-running loop on the main goroutine feeds the watchdog per unit of genuine progress** — the idle ticker, executeUpgrade's progress writes, boot-migrate's ticker, and discovery's artifact-verify loop (per candidate — the 195 fix: a cold eight-candidate verify pass at ~20s/candidate exceeded the 120s budget while making real progress, and systemd killed a progressing daemon, run 29743621767). Per-unit-of-work heartbeats keep hang detection by construction: a loop stuck on ONE unit emits nothing further and still starves the watchdog. A watchdog kill is therefore always evidence of a hang, never of honest slowness — the same discipline that makes the §3 no-spin rule trustworthy.

## What actually went wrong on Rune (the 18-day hang, in two layers)

The canonical statement of the incident that motivated this model (STATBUS-196 AC#4). Two layers, with different fates:

**Layer 1 — the extinct wedge (root cause found and fixed).** During an upgrade, the post-upgrade install fixup re-ran `systemctl enable --now` on the upgrade unit *while that unit was the process running the fixup* — an sd_notify collision that wedged the unit. Three stacked fixes closed it: `61e79e265` lands the terminal row UPDATE *before* the fixup runs, so the vulnerable window no longer exists; `e76505eec` skips `--now` in the fixup when it runs inside an active upgrade; `cb7344dd6` adds the containers-at-target self-heal (`resumeNewSb`'s converged branch) as the net — a box found already serving the target with only the bookkeeping missing gets its row completed instead of being re-driven. This wedge cannot recur: the window is gone, the trigger is guarded, and the net catches the residue.

**Layer 2 — the live class (a box that loops forever while nobody is told).** The wedge was one instance of the broader class this model exists to kill: a box stuck in an automatic loop with no terminal, no bound, and no signal to a human. That class is held down by standing machinery, each piece arc-proven: the recovery **attempt budget** + deterministic-failure **park** (§3/§4 — a failing box reaches alive-idle with one siren, never an unbounded loop), the **restart-bound asserts** in the arc harness (NRestarts bounded + frozen — a churn regression fails the run), and the **deploy-status canary** (STATBUS-069: CI polls the box to a *conclusive* verdict — converged, failed, or parked — so a silent hang becomes a red deployment, not an 18-day mystery). Layer 1 is history; layer 2 is the permanent adversary, and every park, budget, and canary rule above is aimed at it.
