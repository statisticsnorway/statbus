## Goal
A file of identifiers and a few columns (like lat+lon) updates whichever unit, legal unit or establishment, holds each identifier.

## Purpose
Owner 2026-11-22 (better import): Erik's coordinates cover legal units and establishments; today a file is one unit type, so he must split it and pick a definition per type.

## Principle
Matching uses the external identifiers the units already have; a row whose identifier matches no unit, or more than one, is refused in analysis with the reason on the row.

## Details
Builds on dbmsxy (update only the given columns, PATCH_FOR_PORTION_OF). Today import_mode is one of legal_unit, establishment_formal, establishment_informal, generic_unit, legal_relationship; generic_unit (generic_unit_stats_update_*) already matches any unit type by identifier, but only for statistical variables. This task may extend that mode to locations and other columns rather than add a new one; that is the owner's call.

## Depends on
- dbmsxy

## Acceptance
- [ ] [Owner] Chooses whether this extends generic_unit or is a new mode, and which columns it may update; recorded here
- [ ] A file with tax_ident, physical_latitude and physical_longitude for two legal units and one establishment updates exactly those three units' coordinates and nothing else; a SQL test asserts the stored rows
- [ ] A row whose identifier matches no unit, or two units, is refused in analysis with the reason; a test asserts it
