## Goal
A row StatBus ships (custom false) can only be enabled or disabled; its other columns change only through migrations.

## Purpose
Migrations rename codes, fix names and add levels in what StatBus ships, and find those rows by what was shipped. A user's edit to a shipped row makes a migration miss it, fail, or overwrite the user's change. Owner 2026-11-22: we do not prevent customisation (disable a shipped row, add a custom one), we make sure what we provide can be migrated.

## Principle
The database enforces it, whichever path writes (admin page, API, import): each shipped table has a read-only factory twin, and a foreign key over every column except enabled ties a shipped row to its twin. Row-level security cannot do this, since it chooses rows and grants choose columns, but neither says these columns on these rows.

## Details
Owner's design 2026-11-22, played back:
- Twin per table, e.g. sector_factory, written only by migrations, readable by all. Its custom column is always false (CHECK).
- The shipped row's foreign key covers code, name, the other shipped columns and custom, but not enabled. Editing a name breaks it; toggling enabled does not.
- Custom rows (custom true) have no twin and stay freely editable; the key must not be checked for them (e.g. a generated column that is NULL when custom, with MATCH SIMPLE).
- ON UPDATE CASCADE: a migration changes the twin and the shipped rows follow. Reset to factory defaults (50bwaz) becomes a copy from the twin.
Catches for the tests: (1) with MATCH SIMPLE a NULL in any key column skips the check, so a shipped row with a NULL description would be editable; store '' or coalesce in the key columns. (2) A shipped row flipped to custom true would escape; a code in the twin cannot be custom.
Tables with a custom column (doc/db 2026-11-22): activity_category, sector, legal_form, status, unit_size, region_version, country, foreign_participation, legal_rel_type, legal_reorg_type, power_group_type, person_role, tag, data_source, import_definition. Owner: tag, data source and import definition follow the same rule.
